# Authored Tiled prefabs (VOID-026)

Source of truth for the generated prefabs. A `.tmx` here is converted to
`data/prefabs/generated/<same-name>.json`, which is committed alongside it.

    dotnet run --project Void.Tools -- tmx-convert

Run that from the repo root after editing a map. Forgetting is not silent:
`Void.Tests/TiledPrefabConverterTests.cs` reconverts every map in memory and
compares bytes, so a stale generated file fails rung 4 of `tests/check.sh`.

Never hand-edit anything under `data/prefabs/generated/`. Hand-written prefabs
live in `data/prefabs/prefabs.json` and are untouched by the converter.

## Map requirements

| Requirement | Why |
|---|---|
| Orthogonal, finite | A prefab is a fixed tile rectangle. |
| Tile Layer Format: **CSV** | The only encoding the converter reads. Base64/compressed is out of scope. |
| Tile layer `blocks` | Foreground. Required, map-sized. |
| Tile layer `walls` | Background. Required, map-sized. |
| Object layer `markers` | Optional. |
| No flipped or rotated tiles | The runtime format has no flipped tile, so a flip bit is a hard error rather than a structure that silently differs from what you drew. |

Every tile you draw must be mapped in `tileset_map.json`, keyed by tileset name
and local tile id. An unmapped tile is a conversion failure naming the tileset,
the local id and the tile coordinate. The empty tile needs no entry: it becomes
`void:air` / `void:no_wall`.

## Map custom properties

Tiled properties are flat, so the nested parts of the prefab's `constraints`
block use flat explicit names. **An unrecognised property is an error** — a
typo would otherwise leave a constraint quietly at its default.

| Property | Type | Default | Meaning |
|---|---|---|---|
| `prefab_id` | string | *required* | Stable id, e.g. `void:ruin_stone_small_tiled`. Must not collide with a hand-written prefab. |
| `category` | string | *required* | Grouping the placement engine filters and spaces by. |
| `weight` | float | `1` | Relative draw weight. `0` disables; negative fails at load. |
| `constraint_allowed_biomes` | string | empty | Comma-separated biome ids. Empty means **any**. |
| `constraint_allowed_layers` | string | empty | Comma-separated: `surface`, `underground`, `deep`, `void`. Empty means any; an unknown name fails. |
| `constraint_requires_ground` | bool | `false` | Must sit on solid tiles. |
| `constraint_requires_cavern` | bool | `false` | Must sit in carved-out space. |
| `constraint_min_spacing_same_category` | int | `0` | Tiles from prefabs of the same category. |
| `constraint_min_spacing_any_category` | int | `0` | Tiles from any prefab. |
| `constraint_clearance_above` | int | `0` | Empty tiles required above the footprint. |

## Markers

An object's **Class** is the marker type: `boss_spawn`, `entrance`, `chest`,
`spawner`, `decoration`. Anything else fails. The object's pixel position is
floored to a tile coordinate, which must land inside the map. Custom object
properties become the marker's `metadata`, keeping their Tiled type
(string/int/float/bool); other property types fail.

Markers are sorted by y, then x, then type on output, and metadata keys sort
ordinally — the generated bytes must not move when Tiled reorders its objects.
That is a determinism constraint, not tidiness: a prefab that varies between
runs breaks the guarantee that the world seed determines the world.
